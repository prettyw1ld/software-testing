# Практическая работа №5. Функциональное тестирование: разработка сценариев функционального тестирования

## Цель работы

Изучить процесс разработки тестового сценария для проверки функций отдельного модуля веб-приложения.

## Теоретические сведения

### Основные понятия

- **Модульный (unit) тест** проверяет работоспособность модуля программы. Модуль, как правило, — это класс или функция.
- **Тест-кейс** описывается предусловиями, шагами и ожидаемым результатом.
- **Чек-лист** — перечень пунктов, которые необходимо проверить.
- **Jest** — фреймворк для модульного тестирования на JavaScript.

### Структура модульного теста

Тесты в примерах построены по схеме **Arrange — Act — Assert**:

1. **Arrange** — подготовка входных данных и тестируемого объекта.
2. **Act** — вызов тестируемого кода.
3. **Assert** — сравнение фактического результата с ожидаемым.

## Примеры

В примерах используются JavaScript, среда Node.js и фреймворк для модульного тестирования **Jest**. Требуется установленный Node.js и любой редактор кода (например, Visual Studio Code).

### Назначение команд терминала

Команды выполняются в терминале (в Visual Studio Code: меню «Терминал» → «Создать терминал») из папки, где создаётся проект.

| Команда | Что делает |
|---------|------------|
| `mkdir bank` | Создаёт папку проекта `bank` |
| `cd bank` | Переходит в созданную папку |
| `npm init -y` | Создаёт файл `package.json` с настройками проекта по умолчанию (флаг `-y` пропускает вопросы) |
| `npm install --save-dev jest` | Скачивает Jest в папку `node_modules` и записывает его в `package.json` как зависимость для разработки |
| `npm pkg set scripts.test="jest"` | Прописывает в `package.json` скрипт `test`, который запускает Jest |
| `npm test` | Запускает скрипт `test`: Jest находит все файлы `*.test.js`, выполняет тесты и выводит результат в терминал |

В примере 2 используются те же команды, меняется только имя папки (`email-check`).

### Пример 1. Тестирование банковского счёта

Задача: депозитный счёт клиента, который можно пополнять и с которого можно снимать средства. Модульные тесты создаются для сценариев «Снятие со счёта» и «Пополнение счёта».

#### А. Создание проекта

1. Создайте папку проекта, инициализируйте его и установите Jest:

```bash
mkdir bank
cd bank
npm init -y
npm install --save-dev jest
npm pkg set scripts.test="jest"
```

2. Создайте файл `BankAccount.js` со следующим кодом. Код содержит намеренную ошибку в методе `debit`, которая будет найдена тестом.

```js
class BankAccount {
  constructor(customerName, balance) {
    this._customerName = customerName;
    this._balance = balance;
  }

  get customerName() {
    return this._customerName;
  }

  get balance() {
    return this._balance;
  }

  // Снятие со счёта
  debit(amount) {
    if (amount > this._balance) {
      throw new RangeError('amount');
    }
    if (amount < 0) {
      throw new RangeError('amount');
    }
    this._balance += amount; // ошибка: должно быть вычитание
  }

  // Пополнение счёта
  credit(amount) {
    if (amount < 0) {
      throw new RangeError('amount');
    }
    this._balance += amount;
  }
}

module.exports = BankAccount;
```

#### Б. Создание модульного теста

1. Создайте файл `BankAccount.test.js` в корне проекта. Jest автоматически находит файлы с суффиксом `.test.js`.
2. Подключите тестируемый класс через `require`.
3. Создайте тест, который проверяет, что при допустимой сумме со счёта снимается нужное значение. Для теста задаются входное значение и заранее известный результат.

Переменные теста:

- `beginningBalance` — начальный баланс;
- `debitAmount` — сумма снятия;
- `expected` — ожидаемый результат.

```js
const BankAccount = require('./BankAccount');

test('debit with valid amount updates balance', () => {
  // Arrange
  const beginningBalance = 11.99;
  const debitAmount = 4.55;
  const expected = 7.44;
  const account = new BankAccount('Mr. Bryan Walton', beginningBalance);

  // Act
  account.debit(debitAmount);

  // Assert
  const actual = account.balance;
  expect(actual).toBeCloseTo(expected, 3);
});
```

`expect(actual).toBeCloseTo(expected, 3)` сравнивает два числа с точностью до трёх знаков после запятой. Если значения различаются, тест завершается ошибкой. Сравнение через `toBeCloseTo` необходимо, так как числа с плавающей точкой нельзя сравнивать строгим равенством.

#### В. Запуск тестов

Запустите тесты в терминале:

```bash
npm test
```

Тест завершится неудачей — это ожидаемый результат:

```text
Expected: 7.44
Received: 16.54
```

#### Г. Исправление ошибки

1. В файле `BankAccount.js` замените в методе `debit` строку `this._balance += amount;` на `this._balance -= amount;`.
2. Повторно запустите `npm test`. Тест должен пройти.

#### Д. Добавление новых тестов

1. Создайте тест для случая, когда сумма снятия меньше нуля. Матчер `toThrow(RangeError)` подтверждает, что выброшено исключение нужного типа. Тест завершится неудачей, если исключение не выброшено или выброшено исключение другого типа. Например, если временно заменить в методе `debit` `RangeError` на общий `Error`, тест должен упасть.

```js
test('debit when amount is less than zero should throw RangeError', () => {
  // Arrange
  const beginningBalance = 11.99;
  const debitAmount = -100.0;
  const account = new BankAccount('Mr. Bryan Walton', beginningBalance);

  // Act и Assert
  expect(() => account.debit(debitAmount)).toThrow(RangeError);
});
```

2. Создайте тест для случая, когда сумма снятия превышает баланс. Назовите его `debit when amount is more than balance should throw RangeError` и скопируйте в него тело предыдущего теста. Задайте `debitAmount = 20.0`.

1. Запустите тесты. Оба теста проходят, но неизвестно, какое именно условие метода `debit` вызвало исключение. Чтобы различать отрицательную сумму и сумму, превышающую баланс, выполните рефакторинг тестируемого кода.

```js
class BankAccount {
  static DEBIT_AMOUNT_EXCEEDS_BALANCE_MESSAGE = 'Debit amount exceeds balance';
  static DEBIT_AMOUNT_LESS_THAN_ZERO_MESSAGE = 'Debit amount is less than zero';

  // остальной код класса без изменений
```

3. Измените два условия в методе `debit`:

```js
if (amount > this._balance) {
  throw new RangeError(BankAccount.DEBIT_AMOUNT_EXCEEDS_BALANCE_MESSAGE);

  throw new RangeError(BankAccount.DEBIT_AMOUNT_LESS_THAN_ZERO_MESSAGE);
```

### Пример 2. Модульный тест проверки email

В примере тестируется функция проверки корректности написания email.

1. Создайте папку проекта, инициализируйте его и установите Jest:

```bash
mkdir email-check
cd email-check
npm init -y
npm install --save-dev jest
npm pkg set scripts.test="jest"
```

2. Создайте два файла в корне проекта: `email.js` (тестируемый модуль) и `email.test.js` (модульные тесты).
3. Напишите тестируемую функцию в файле `email.js`:

```js
function isValidEmail(email) {
  if (typeof email !== 'string') {
    return false;
  }
  const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return pattern.test(email);
}

module.exports = { isValidEmail };
```

4. Подключите модуль в файле тестов через `require` — после этого функция доступна в тестах.
5. Напишите несколько модульных тестов в файле `email.test.js`:

```js
const { isValidEmail } = require('./email');

describe('isValidEmail', () => {
  test('correct address returns true', () => {
    expect(isValidEmail('user@example.com')).toBe(true);
  });

  test.each([
    ['address without @', 'userexample.com'],
    ['address without domain', 'user@'],
    ['address without local part', '@example.com'],
    ['address without dot in domain', 'user@example'],
    ['address with space', 'us er@example.com'],
    ['empty string', ''],
  ])('%s returns false', (_name, email) => {
    expect(isValidEmail(email)).toBe(false);
  });

  test('non-string value returns false', () => {
    expect(isValidEmail(null)).toBe(false);
  });
});
```

6. Запустите тесты в терминале и проверьте результат:

```bash
npm test
```

Пример создаёт простой тест проверки email. Если функция большая и в неё вносятся изменения, модульные тесты сразу покажут, что логика работы программы нарушена.
