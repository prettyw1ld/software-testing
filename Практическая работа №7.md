# Практическая работа №7. Признаки плохого кода

## Цель работы

Изучить признаки плохого кода с точки зрения тестировщика.

## Теоретические сведения

Ниже перечислены приёмы, которые помогают избежать плохого кода. Примеры кода к каждому приёму приведены в разделе «Примеры».

### Приём 1. Имена переменных

- Не используйте местоимения в именах, а также слишком длинные имена.
- Имя должно отражать семантику, а не тип переменной. Имена вида `s`, `list`, `array` не дают полезной информации.
- В имени отражайте существенные особенности. Например, если переменная типа `Date` хранит только дату, назовите её `date`.
- Избегайте однобуквенных имён. Общее правило: чем больше область видимости, тем подробнее должно быть имя.
- Иногда арифметическое выражение понятнее его значения. Запись `24 * 60 * 60` проще проверить на корректность, чем `86400`.

### Приём 2. Объявление переменных в начале логического блока

Переменные объявляются в начале логического блока, в котором они используются, а **не** в начале функции или программы.

Все программные системы **иерархичны**: программы делятся на пакеты (группирующие сущности), пакеты на классы, классы на отдельные функции. Данные, относящиеся к модулю, принято объявлять в начале этого модуля: свойства класса в начале определения класса, локальные переменные в начале функции.

Функции не являются последним уровнем иерархии. Любая нетривиальная функция состоит из блоков, каждый из которых реализует отдельный шаг алгоритма. Блоки могут отделяться друг от друга пустой строкой. У блока тоже бывают **локальные переменные**: они объявляются в начале блока и используются только в его пределах. Это упрощает комментирование блока.

### Приём 3. Возврат результата через return, а не через параметр

Функция должна возвращать результат, зависящий от её параметров, а **не** принимать результат в качестве аргумента.

Понятие функции (в математике и в программировании) означает вычисление результата, зависящего от аргументов. В коде должно быть видно, что является результатом, а что аргументами: `результат = функция(аргумент1, аргумент2)`. Должно быть понятно, от чего функция зависит и что она возвращает.

### Приём 4. Локальные функции

Программные системы (объектно-ориентированные и процедурные) иерархичны и делятся на вложенные друг в друга модули. Каждый модуль располагает своими локальными ресурсами, которые используются только в его рамках. Локальные переменные являются ресурсами функции, но не единственными: подфункции, классы и структуры тоже подчинены функции и используются только в её рамках.

Локальные функции поддерживаются как в динамических языках (JavaScript, Python), так и в классических (Java). Используйте эту возможность: вспомогательную функцию, нужную только одной функции, объявляйте внутри неё.

### Приём 5. Вложенность блоков и конструкция else if

Уровень вложенности блока должен соответствовать его иерархическому положению в программе. Блоки кода с одинаковым уровнем вложенности относятся к одному уровню иерархии. Блоки с большим уровнем вложенности подчинены блокам с меньшей вложенностью. Пишите код так, чтобы уровень вложенности соответствовал уровню иерархии блока.

### Приём 6. Именованные параметры функции

Параметры нетривиальной функции должны задаваться по осмысленному имени, а **не** по положению в списке аргументов.

Осмысленные имена должны быть у уникальных переменных, которые обрабатываются отдельно. Осмысленного имени могут не иметь неуникальные переменные, входящие в коллекцию и обрабатываемые не по отдельности, а вместе, в цикле.

### Приём 7. Иерархия вложенных данных

При работе с вложенными данными соблюдайте правила иерархии: свойства хранятся внутри объекта, а **не** объект внутри свойства. Связанные данные должны иметь общий контейнер. Тогда объект выглядит как объект и не распадается на множество независимых свойств. С объектом можно работать как с единым целым, например передавать его в функцию одним параметром.

### Приём 8. Свойства для данных, методы для поведения

Доступ к данным выполняется через свойства, а **не** через методы. У полей и методов объекта разное назначение:

- поля хранят данные;
- методы реализуют поведение объекта.

Должно быть видно, где идёт работа с данными, а где реализуется логика поведения:

```js
objObject.property1 = 'value1';     // работа с данными
objObject.doSomething(param1, param2); // поведение объекта
```

Не смешивайте данные объекта и его поведение. Естественная конструкция для доступа к данным это оператор присваивания. Вызов метода, то есть сами круглые скобки, подразумевает реализацию поведения.

## Примеры

Для запуска примеров нужен Node.js. Сохраните код в файл и выполните `node имя-файла.js`. В каждом примере исходная и исправленная версии выдают одинаковый результат: исправление не должно менять поведение программы.

### Пример 1. Имена переменных

#### А. Плохой код

```js
function getViewsPerSecond(views, t) {
  const n = 86400;
  const viewsCount = views.filter(v => v.timestamp.toDateString() === t.toDateString()).length;
  return viewsCount / n;
}

const views = [
  { timestamp: new Date('2026-10-04T10:00:00') },
  { timestamp: new Date('2026-10-04T12:30:00') },
  { timestamp: new Date('2026-10-03T09:00:00') },
];
console.log(getViewsPerSecond(views, new Date('2026-10-04')));
```

#### Б. Исправленный код

Параметр `t` переименован в `date`, константа `n` в `secondsInDay`, значение `86400` записано как `24 * 60 * 60`.

```js
function getViewsPerSecond(views, date) {
  const secondsInDay = 24 * 60 * 60;
  const viewsCount = views.filter(view => view.timestamp.toDateString() === date.toDateString()).length;
  return viewsCount / secondsInDay;
}

const views = [
  { timestamp: new Date('2026-10-04T10:00:00') },
  { timestamp: new Date('2026-10-04T12:30:00') },
  { timestamp: new Date('2026-10-03T09:00:00') },
];
console.log(getViewsPerSecond(views, new Date('2026-10-04')));
```

#### В. Результат запуска обеих версий

```text
0.000023148148148148147
```

### Пример 2. Объявление переменных в начале блока

#### А. Плохой код

Все переменные объявлены в начале функции, хотя `line` нужна только в теле цикла, а `discount` только в условии.

```js
function printReport(orders) {
  let total = 0;
  let discount = 0;
  let i;
  let line;
  for (i = 0; i < orders.length; i++) {
    line = orders[i].name + ': ' + orders[i].price;
    console.log(line);
    total += orders[i].price;
  }
  if (total > 1000) {
    discount = total * 0.1;
    console.log('Скидка: ' + discount);
  }
}

printReport([{ name: 'Мышь', price: 700 }, { name: 'Клавиатура', price: 900 }]);
```

#### Б. Исправленный код

```js
function printReport(orders) {
  let total = 0;
  for (const order of orders) {
    const line = `${order.name}: ${order.price}`;
    console.log(line);
    total += order.price;
  }
  if (total > 1000) {
    const discount = total * 0.1;
    console.log(`Скидка: ${discount}`);
  }
}

printReport([{ name: 'Мышь', price: 700 }, { name: 'Клавиатура', price: 900 }]);
```

#### В. Результат запуска обеих версий

```text
Мышь: 700
Клавиатура: 900
Скидка: 160
```

### Пример 3. Возврат результата через return

#### А. Плохой код

```js
function calculateTotal(prices, result) {
  let sum = 0;
  for (const price of prices) {
    sum += price;
  }
  result.total = sum;
}

const result = {};
calculateTotal([100, 250, 50], result);
console.log(result.total);
```

#### Б. Исправленный код

```js
function calculateTotal(prices) {
  let sum = 0;
  for (const price of prices) {
    sum += price;
  }
  return sum;
}

const total = calculateTotal([100, 250, 50]);
console.log(total);
```

#### В. Результат запуска обеих версий

```text
400
```

### Пример 4. Локальные функции

#### А. Плохой код

Функция `isAdult` нужна только внутри `getAdultNames`, но объявлена на уровне модуля.

```js
function isAdult(user) {
  return user.age >= 18;
}

function getAdultNames(users) {
  return users.filter(isAdult).map(user => user.name);
}

console.log(getAdultNames([{ name: 'Аня', age: 17 }, { name: 'Борис', age: 25 }]));
```

#### Б. Исправленный код

```js
function getAdultNames(users) {
  function isAdult(user) {
    return user.age >= 18;
  }

  return users.filter(isAdult).map(user => user.name);
}

console.log(getAdultNames([{ name: 'Аня', age: 17 }, { name: 'Борис', age: 25 }]));
```

#### В. Результат запуска обеих версий

```text
[ 'Борис' ]
```

### Пример 5. Вложенность блоков и else if

#### А. Плохой код

Страна доставки и вес посылки относятся к разным уровням иерархии, но условия записаны на одном уровне вложенности.

```js
function getShippingCost(order) {
  if (order.country !== 'RU') {
    return 2000;
  } else if (order.weight > 20) {
    return 1000;
  } else if (order.weight > 5) {
    return 500;
  } else {
    return 200;
  }
}

console.log(getShippingCost({ country: 'DE', weight: 1 }));
console.log(getShippingCost({ country: 'RU', weight: 7 }));
```

#### Б. Исправленный код

Выбор по стране находится на верхнем уровне. Проверки веса подчинены ветке `RU` и вложены в неё.

```js
function getShippingCost(order) {
  if (order.country !== 'RU') {
    return 2000;
  } else {
    if (order.weight > 20) {
      return 1000;
    } else {
      if (order.weight > 5) {
        return 500;
      } else {
        return 200;
      }
    }
  }
}

console.log(getShippingCost({ country: 'DE', weight: 1 }));
console.log(getShippingCost({ country: 'RU', weight: 7 }));
```

#### В. Результат запуска обеих версий

```text
2000
500
```

### Пример 6. Именованные параметры

#### А. Плохой код

По вызову `createUser('Иван', 'Петров', 25, true, false)` непонятно, что означают `true` и `false`.

```js
function createUser(firstName, lastName, age, isActive, isAdmin) {
  return { firstName, lastName, age, isActive, isAdmin };
}

console.log(createUser('Иван', 'Петров', 25, true, false));
```

#### Б. Исправленный код

В JavaScript именованные параметры реализуются передачей объекта и деструктуризацией в списке параметров.

```js
function createUser({ firstName, lastName, age, isActive, isAdmin }) {
  return { firstName, lastName, age, isActive, isAdmin };
}

console.log(createUser({
  firstName: 'Иван',
  lastName: 'Петров',
  age: 25,
  isActive: true,
  isAdmin: false,
}));
```

#### В. Результат запуска обеих версий

```text
{
  firstName: 'Иван',
  lastName: 'Петров',
  age: 25,
  isActive: true,
  isAdmin: false
}
```

### Пример 7. Иерархия вложенных данных

#### А. Плохой код

Данные клиента разбросаны по независимым свойствам заказа, их приходится передавать в функцию по одному.

```js
const order = {
  id: 1,
  customerName: 'Иван',
  customerPhone: '+7 900 000-00-00',
  customerEmail: 'ivan@example.com',
};

function sendNotification(name, phone, email) {
  console.log(`Уведомление для ${name} (${phone}, ${email})`);
}

sendNotification(order.customerName, order.customerPhone, order.customerEmail);
```

#### Б. Исправленный код

Связанные данные собраны в объект `customer`, который передаётся как единое целое.

```js
const order = {
  id: 1,
  customer: {
    name: 'Иван',
    phone: '+7 900 000-00-00',
    email: 'ivan@example.com',
  },
};

function sendNotification(customer) {
  console.log(`Уведомление для ${customer.name} (${customer.phone}, ${customer.email})`);
}

sendNotification(order.customer);
```

#### В. Результат запуска обеих версий

```text
Уведомление для Иван (+7 900 000-00-00, ivan@example.com)
```

### Пример 8. Свойства для данных, методы для поведения

#### А. Плохой код

Для чтения и записи данных используются методы `getTitle`, `getPrice`, `setPrice`.

```js
class Product {
  constructor(title, price) {
    this._title = title;
    this._price = price;
  }
  getTitle() { return this._title; }
  getPrice() { return this._price; }
  setPrice(price) { this._price = price; }
  applyDiscount(percent) { this._price = this._price * (1 - percent / 100); }
}

const product = new Product('Мышь', 1000);
product.setPrice(1200);
product.applyDiscount(10);
console.log(product.getTitle(), product.getPrice());
```

#### Б. Исправленный код

Данные читаются и записываются через свойства. Метод остался только у поведения (`applyDiscount`).

```js
class Product {
  constructor(title, price) {
    this.title = title;
    this.price = price;
  }
  applyDiscount(percent) {
    this.price = this.price * (1 - percent / 100);
  }
}

const product = new Product('Мышь', 1000);
product.price = 1200;
product.applyDiscount(10);
console.log(product.title, product.price);
```

#### В. Результат запуска обеих версий

```text
Мышь 1080
```
