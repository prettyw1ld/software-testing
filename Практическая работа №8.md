# Практическая работа №8. Исключительные ситуации

## Цель работы

Изучить способы тестирования обработки исключительных ситуаций в программе с помощью `try...catch...finally`.

## Теоретические сведения

### Исключения в JavaScript

В JavaScript и Node.js определено множество исключений (англ. Exception). Исключение это объект, наследующий от класса `Error`. Основные встроенные типы и системные ошибки Node.js приведены в таблице.

| Исключение | Когда возникает |
| --- | --- |
| `Error` | Базовый класс всех исключений. Используется для собственных ошибок общего вида |
| `TypeError` | Значение имеет не тот тип, который требуется для операции. Например, чтение свойства у `null` |
| `RangeError` | Значение вне допустимого диапазона. Например, `new Array(-1)`, `(1).toFixed(101)`, деление `BigInt` на ноль |
| `SyntaxError` | Неверный синтаксис. В рабочем коде чаще всего возникает при `JSON.parse` для строки неверного формата |
| `ReferenceError` | Обращение к необъявленной переменной |
| `URIError` | Некорректная строка при вызове `decodeURIComponent` и подобных функций |
| `AggregateError` | Группа ошибок в одной. Например, когда отклонены все промисы в `Promise.any` |
| Системная ошибка Node.js | Ошибка окружения. Это `Error` с полем `code`: `ENOENT` (файл или каталог не найден), `EACCES` (нет прав доступа), `EMFILE` (слишком много открытых файлов) |
| `uncaughtException`, `unhandledRejection` | События объекта `process`. Возникают, если исключение или отклонённый промис остались необработанными |

Нехватка памяти для выполнения программы (`OutOfMemoryException` в .NET) в JavaScript проявляется двумя способами: попытка создать массив недопустимой длины даёт перехватываемый `RangeError`, а исчерпание кучи завершает процесс аварийно, и перехватить такую ошибку нельзя.

### Отличия от .NET

В JavaScript часть ситуаций, в которых .NET генерирует исключение, исключением не является:

- деление на ноль даёт `Infinity`, `-Infinity` или `NaN`;
- обращение к элементу массива за пределами индексов даёт `undefined`;
- преобразование строки в число через `Number('abc')` даёт `NaN`.

Поэтому исключения, аналогичные `DivideByZeroException`, `IndexOutOfRangeException` и `FormatException`, нужно генерировать самостоятельно оператором `throw` после проверки значений.

### Структурированная обработка исключений

Программирование со структурированной обработкой исключений использует четыре связанные сущности:

- тип (класс), который представляет детали исключения;
- функция или метод, который генерирует экземпляр исключения (`throw`) при соответствующих обстоятельствах;
- блок кода на вызывающей стороне, который обращается к функции, где может произойти исключение;
- блок кода на вызывающей стороне, который перехватывает (`catch`) и обрабатывает исключение, если оно возникло.

Необходимо тестировать правильность **перехвата исключений**. Для обработки ошибочных ситуаций программа делится на блоки трёх типов:

- Блоки **try** инкапсулируют код, формирующий часть нормальных действий программы, который потенциально может столкнуться с серьёзными ошибочными ситуациями.
- Блоки **catch** инкапсулируют код, обрабатывающий ошибочные ситуации из блока `try`. Это удобное место для протоколирования ошибок.
- Блоки **finally** инкапсулируют код, который освобождает ресурсы или выполняет другие завершающие действия. Блок выполняется независимо от того, было ли сгенерировано исключение.

Основу обработки исключений составляет пара ключевых слов `try` и `catch`. В JavaScript у одного `try` может быть только один блок `catch`. Если нужны разные обработчики для разных типов исключений, тип проверяется внутри `catch` оператором `instanceof`:

```js
try {
  // Блок кода, проверяемый на наличие ошибок.
} catch (error) {
  if (error instanceof ExcepType1) {
    // Обработчик исключения типа ExcepType1.
  } else if (error instanceof ExcepType2) {
    // Обработчик исключения типа ExcepType2.
  } else {
    throw error; // Остальные исключения передаются выше.
  }
} finally {
  // Освобождение ресурсов. Выполняется всегда.
}
```

Когда в блоке `try` генерируется исключение, управление передаётся в `catch`, а переменная `error` получает объект исключения. Переменную можно не указывать, если обработчику не нужен объект исключения: `catch { }`.

Выбрасывайте объекты `Error` или его наследников, а не строки и числа: так сохраняется стек вызовов.

### Асинхронный код

Ошибка в `async`-функции превращается в отклонённый промис. Перехватить её можно блоком `try...catch` вокруг `await`. Без перехвата возникает необработанное отклонение (`unhandledRejection`), и Node.js завершает процесс с ненулевым кодом возврата.

### Связь с безопасностью

В списке OWASP Top 10:2025 неправильная обработка исключительных ситуаций выделена в отдельную категорию A10:2025 Mishandling of Exceptional Conditions. Она описывает случаи, когда программа не предотвращает, не обнаруживает и не обрабатывает необычные ситуации. Последствия: сбои, неожиданное поведение, уязвимости. Один из сценариев категории: приложение перехватывает исключения при загрузке файлов, но не освобождает ресурсы, что приводит к отказу в обслуживании. Освобождение ресурсов в блоке `finally` предотвращает такой сценарий.

### Пример 1. Деление на ноль и ввод не числа

#### А. Поведение без исключений

В JavaScript перечисленные операции не генерируют исключений.

```js
console.log(5 / 0);
console.log(-5 / 0);
console.log(0 / 0);
console.log([1, 2, 3][10]);
console.log(Number('abc'));
```

```text
Infinity
-Infinity
NaN
undefined
NaN
```

#### Б. Код с генерацией и обработкой исключений

Функция `parseNumber` генерирует `TypeError` для не числа (аналог `FormatException`), функция `divide` генерирует `RangeError` при делении на ноль (аналог `DivideByZeroException`). Числа передаются аргументами командной строки.

```js
function parseNumber(text) {
  const value = Number(text);
  if (text.trim() === '' || Number.isNaN(value)) {
    throw new TypeError(`Значение "${text}" не является числом`);
  }
  return value;
}

function divide(dividend, divisor) {
  if (divisor === 0) {
    throw new RangeError('Деление на ноль');
  }
  return dividend / divisor;
}

try {
  const dividend = parseNumber(process.argv[2]);
  const divisor = parseNumber(process.argv[3]);
  console.log(`Результат: ${divide(dividend, divisor)}`);
} catch (error) {
  if (error instanceof RangeError) {
    console.log(`Ошибка вычисления: ${error.message}`);
  } else if (error instanceof TypeError) {
    console.log(`Ошибка ввода: ${error.message}`);
  } else {
    throw error;
  }
}
```

#### В. Корректный ввод

В JavaScript нет целочисленного типа, поэтому результат `5 / 7` не округляется до 0. Для целой части используйте `Math.trunc`.

```bash
node divide.js 5 7
```

```text
Результат: 0.7142857142857143
```

#### Г. Деление на ноль

```bash
node divide.js 5 0
```

```text
Ошибка вычисления: Деление на ноль
```

#### Д. Ввод не числа

```bash
node divide.js 5 abc
```

```text
Ошибка ввода: Значение "abc" не является числом
```

### Пример 2. Работа с файлами

#### А. Код

Программа обращается к файлу, который был удалён. Здесь файл удаляется программно, но пользователь может удалить его и случайно. Отсутствие файла определяется по коду системной ошибки `ENOENT`.

```js
const fs = require('fs');

const fileName = 'data.txt';
fs.writeFileSync(fileName, 'Содержимое файла');
fs.unlinkSync(fileName);

try {
  const text = fs.readFileSync(fileName, 'utf8');
  console.log(text);
} catch (error) {
  if (error.code === 'ENOENT') {
    console.log(`Файл ${fileName} не найден`);
  } else {
    throw error;
  }
}
```

#### Б. Результат

```text
Файл data.txt не найден
```

### Пример 3. Массивы

#### А. Код

Обращение к элементу за границами массива в JavaScript возвращает `undefined`, поэтому проверка индекса и генерация исключений выполняются в коде. Индекс передаётся аргументом командной строки.

```js
const numbers = [10, 20, 30];

function getElement(array, indexText) {
  const index = Number(indexText);
  if (!Number.isInteger(index)) {
    throw new TypeError(`Индекс "${indexText}" не является целым числом`);
  }
  if (index < 0 || index >= array.length) {
    throw new RangeError(`Индекс ${index} вне диапазона 0..${array.length - 1}`);
  }
  return array[index];
}

try {
  console.log(`Элемент: ${getElement(numbers, process.argv[2])}`);
} catch (error) {
  if (error instanceof RangeError || error instanceof TypeError) {
    console.log(`Ошибка: ${error.message}`);
  } else {
    throw error;
  }
}
```

#### Б. Индекс вне диапазона

```bash
node array.js 5
```

```text
Ошибка: Индекс 5 вне диапазона 0..2
```

#### В. Введено не число

```bash
node array.js abc
```

```text
Ошибка: Индекс "abc" не является целым числом
```

#### Г. Исключения нет

```bash
node array.js 1
```

```text
Элемент: 20
```

### Пример 4. Собственный класс исключения

#### А. Класс Guest

Класс `Guest` проверяет возраст и генерирует исключение `ArgumentOutOfRangeError`. Оно наследует от `RangeError` и хранит имя параметра, вызвавшего ошибку (`paramName`), и сообщение. Сохраните код в файл `guest.js`.

```js
const minimumRequiredAge = 18;

class ArgumentOutOfRangeError extends RangeError {
  constructor(paramName, message) {
    super(message);
    this.name = 'ArgumentOutOfRangeError';
    this.paramName = paramName;
  }
}

class Guest {
  constructor(name, age) {
    if (age < minimumRequiredAge) {
      throw new ArgumentOutOfRangeError(
        'age',
        `Все гости должны быть ${minimumRequiredAge} лет или старше.`
      );
    }
    this.name = name;
    this.age = age;
  }
}

module.exports = { Guest, ArgumentOutOfRangeError };
```

#### Б. Перехват исключения

Исключение этого типа перехватывается в вызывающем коде, чтобы показать ранее созданное сообщение. Сохраните код в файл `app.js` рядом с `guest.js`. Возраст передаётся аргументом командной строки.

```js
const { Guest, ArgumentOutOfRangeError } = require('./guest');

try {
  const guest = new Guest('Иван', Number(process.argv[2]));
  console.log(`Гость ${guest.name}, ${guest.age} лет, допущен`);
} catch (error) {
  if (error instanceof ArgumentOutOfRangeError) {
    console.log(`Ошибка в параметре ${error.paramName}: ${error.message}`);
  } else {
    throw error;
  }
}
```

#### В. Возраст меньше допустимого

```bash
node app.js 15
```

```text
Ошибка в параметре age: Все гости должны быть 18 лет или старше.
```

#### Г. Допустимый возраст

```bash
node app.js 25
```

```text
Гость Иван, 25 лет, допущен
```

### Пример 5. Что будет, если исключение не перехвачено

Перехват исключения позволяет избежать аварийного завершения программы. Исключение, которое не перехвачено ни одним фрагментом кода, перехватывает среда выполнения: Node.js выводит сообщение об ошибке со стеком вызовов и прерывает выполнение программы. Это допустимо при отладке, но не при работе у пользователя.

#### А. Синхронный код без перехвата

```js
const config = JSON.parse('{port:');
console.log(config.port);
```

Начало вывода (текст сообщения зависит от версии Node.js, пути в стеке вызовов будут другими):

```text
SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)
    at JSON.parse (<anonymous>)
```

Код возврата процесса равен 1. Проверить его можно командой `echo $?` (Linux, macOS) или `$LASTEXITCODE` (PowerShell).

#### Б. Тот же код с перехватом

```js
try {
  const config = JSON.parse('{port:');
  console.log(config.port);
} catch (error) {
  if (error instanceof SyntaxError) {
    console.log('Некорректный формат конфигурации');
  } else {
    throw error;
  }
}
```

```text
Некорректный формат конфигурации
```

#### В. Асинхронный код без перехвата

Отклонённый промис без обработчика тоже завершает процесс с кодом 1.

```js
const fs = require('fs/promises');

async function main() {
  const text = await fs.readFile('missing.txt', 'utf8');
  console.log(text);
}

main();
```

Начало вывода:

```text
Error: ENOENT: no such file or directory, open 'missing.txt'
```

#### Г. Асинхронный код с перехватом

```js
const fs = require('fs/promises');

async function main() {
  try {
    const text = await fs.readFile('missing.txt', 'utf8');
    console.log(text);
  } catch (error) {
    console.log(`Не удалось прочитать файл: ${error.code}`);
  }
}

main();
```

```text
Не удалось прочитать файл: ENOENT
```

### Пример 6. Блок finally

#### А. Код

Функция открывает файл, читает его и должна закрыть файл в любом случае: при успешном чтении, при пустом файле (исключение в `try`) и при отсутствии файла (исключение при открытии, закрывать нечего).

```js
const fs = require('fs/promises');

async function readFirstLine(fileName) {
  let fileHandle;
  try {
    fileHandle = await fs.open(fileName, 'r');
    const content = await fileHandle.readFile({ encoding: 'utf8' });
    if (content.trim() === '') {
      throw new Error('Файл пуст');
    }
    return content.split('\n')[0];
  } catch (error) {
    console.log(`Ошибка: ${error.message}`);
    return null;
  } finally {
    if (fileHandle) {
      await fileHandle.close();
      console.log('Файл закрыт');
    }
  }
}

async function main() {
  await fs.writeFile('empty.txt', '');
  await fs.writeFile('full.txt', 'Первая строка\nВторая строка');
  console.log(await readFirstLine('full.txt'));
  console.log(await readFirstLine('empty.txt'));
  console.log(await readFirstLine('missing.txt'));
}

main();
```

#### Б. Результат

Строка «Файл закрыт» выводится до результата функции, потому что `finally` выполняется до возврата значения вызывающему коду. Для `empty.txt` сначала выводится ошибка из `catch`, затем выполняется `finally`. Для `missing.txt` файл не открыт, поэтому `finally` ничего не закрывает.

```text
Файл закрыт
Первая строка
Ошибка: Файл пуст
Файл закрыт
null
Ошибка: ENOENT: no such file or directory, open 'missing.txt'
null
```

### Пример 7. Автоматическая проверка исключений в Jest

Обработку исключений можно проверять автоматическими тестами. Матчер `toThrow` принимает функцию, которая должна выбросить исключение. Установка и запуск Jest описаны в практической работе №5. Сохраните тест в файл `guest.test.js` рядом с `guest.js` из примера 4.

#### А. Код теста

```js
const { Guest, ArgumentOutOfRangeError } = require('./guest');

describe('Guest', () => {
  test('создаёт гостя, которому есть 18 лет', () => {
    expect(new Guest('Иван', 18).age).toBe(18);
  });

  test('выбрасывает ArgumentOutOfRangeError для возраста младше 18', () => {
    expect(() => new Guest('Иван', 15)).toThrow(ArgumentOutOfRangeError);
  });

  test('сообщение об ошибке содержит минимальный возраст', () => {
    expect(() => new Guest('Иван', 15)).toThrow('18 лет или старше');
  });

  test('ошибка хранит имя параметра', () => {
    try {
      new Guest('Иван', 15);
    } catch (error) {
      expect(error.paramName).toBe('age');
    }
  });
});
```

#### Б. Запуск

```bash
npx jest guest.test.js
```

```text
PASS ./guest.test.js
  Guest
    ✓ создаёт гостя, которому есть 18 лет
    ✓ выбрасывает ArgumentOutOfRangeError для возраста младше 18
    ✓ сообщение об ошибке содержит минимальный возраст
    ✓ ошибка хранит имя параметра

Tests:       4 passed, 4 total
```
