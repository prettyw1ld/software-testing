
# ПРАКТИЧЕСКАЯ РАБОТА №3
## Планирование мероприятий по тестированию информационной системы

### Цель работы
Научиться планировать тестирование конкретной информационной системы: определить, **что** тестируется, **что не** тестируется, **чем**, **в каком окружении**, **какими силами**, **с какими рисками** и **в какие сроки**, и оформить это в виде одностраничного тест-плана в табличной форме.

### Результат работы
1. Сформулированное индивидуальное задание.
2. Заполненный тест-план (таблица) на одну страницу.
3. Ответы на контрольные вопросы.
4. Вывод по работе.

---

### 1. Теоретический минимум

Планирование — деятельность по оптимальному распределению ресурсов и постановке задач для успешного проведения процесса.
Тест-план — документ, который фиксирует это распределение применительно к тестированию.

Способы представления тест-плана:

| Способ | Пример инструмента |
|---|---|
| Традиционный документ | Microsoft Word, Microsoft Excel |
| Визуализация | таблицы, диаграммы, короткие схемы |
| Система управления тестированием (TMS) | qTest, Zephyr, TestRail |

Требование к объёму: **1 страница** — только та информация, которую читатель обязан знать .

---

### 2. Ход работы

**Шаг 1. Выберите объект тестирования**:
- настольное приложение;
- сайт учебного заведения;
- сайт интернет-магазина;
- информационная система учреждения;
- инструментальное средство ИТ;
- операционная система;
- тематика своего курсового проекта или собственный вариант.

**Шаг 2. Внесите конкретику.** Примеры: «Тестирование сайта КГАПОУ "Авиатехникум"», «Тестирование сайта онлайн магазина "Лабубушоп" (магазин по продаже монстриков)».

**Шаг 3.** В отчёте после цели работы запишите индивидуальное задание.

**Шаг 4.** Заполните шаблон тест-плана (раздел 3).

**Шаг 5.** Ответьте на контрольные вопросы и сделайте вывод.

### 4. Пример заполнения: «Сайт Авиатехникума»

| № | Раздел | Содержание |
|---|---|---|
| 1 | Введение | Тестирование проводится по заданию службы контроля качества техникума |
| 2 | Объект тестирования | Публичный сайт КГАПОУ «Авиатехникум» |
| 3 | Будет сделано | Функциональное тестирование; поиск проблемных (битых) ссылок; тестирование мобильной совместимости; поиск ошибок в HTML и CSS; нагрузочное тестирование; тестирование юзабилити |
| 4 | Не будет сделано | Автоматизация всех видов тестирования; регрессионное тестирование |
| 5 | Входные условия | Имеется необходимая документация; компоненты системы готовы к тестированию |
| 6 | Выходные условия | Найденные дефекты задокументированы тестировщиком |
| 7 | Окружения | Windows; браузеры Google Chrome, Firefox, Opera |
| 8 | Инструменты | qTest, Selenium, IBM Rational Functional Tester, CSS Validator, Mobile Checker |
| 9 | Ресурсы | Тестировщики, модераторы, оценщик качества, тестировщик структуры хранения |
| 10 | Риски | Неправильно спроектированная архитектура; неправильные приоритеты; недоступность тестовых сред; некорректная оценка затрат/сроков |
| 11 | Допущения | Проведение **не всех** тестов на 100 % |
| 12 | Оценки и сроки | Тестирование — 8 дней; приёмочная документация (тест-план, чек-лист) — 2 дня |
