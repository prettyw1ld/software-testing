# Практическая работа №11. Интеграционное тестирование

## Цель работы

Практически освоить интеграцию модулей и интеграционное тестирование их взаимодействия.

## Теоретические сведения

### Модуль и интеграция модулей

**Модуль** — самостоятельная часть программы с собственным интерфейсом. В Node.js модулем считается файл JavaScript, который экспортирует функции или классы через `module.exports` и подключается в другом файле через `require`. Модулем также является внешний пакет npm, например драйвер базы данных `mysql2`.

Модули разрабатываются и тестируются отдельно, а затем объединяются в программу. **Интеграция модулей** — их объединение в общую систему, при котором модули обмениваются данными через свои интерфейсы.

Пример: проект из нескольких файлов, каждый из которых отвечает за свою задачу. Класс пользователя описывает данные, модуль доступа к данным выполняет запросы к базе, модуль сравнения проверяет совпадение объектов. Каждый файл можно проверить отдельно, но корректность программы определяется тем, как они работают вместе.

### Интеграционное тестирование

**Интеграционное тестирование** проверяет взаимодействие модулей между собой и с внешними системами: базой данных, файловой системой, сетевыми сервисами. Модульный тест проверяет один модуль в изоляции, интеграционный — передачу данных через границу модулей: формат данных, порядок вызовов, обработку ответов.

Интеграционное тестирование называют **тестированием архитектуры системы**: оно проверяет, правильно ли спроектированы связи между компонентами и соответствуют ли друг другу их интерфейсы.

### Заглушки и драйверы

Если часть модулей ещё не готова, их заменяют временными объектами:

- **заглушка** (stub) — упрощённая замена вызываемого модуля, которая возвращает заранее заданный результат;
- **драйвер** (driver) — временный модуль, который вызывает тестируемый модуль и передаёт ему данные вместо ещё не написанного вызывающего модуля.

В Jest заглушки создаются функциями `jest.fn()` и `jest.mock()`.

### Методы интеграционного тестирования

| Метод | Порядок объединения | Что требуется | Особенность |
| --- | --- | --- | --- |
| **Монолитный** (big bang) | Все модули объединяются и тестируются сразу | Заглушки и драйверы не нужны | Ошибку трудно локализовать, тестирование начинается поздно |
| **Нисходящий** (top-down) | От модулей верхнего уровня к нижним | Заглушки для нижних модулей | Рано проверяется общая логика программы |
| **Восходящий** (bottom-up) | От модулей нижнего уровня к верхним | Драйверы для вызова нижних модулей | Рано проверяется работа с данными и внешними системами |
| **Смешанный** (sandwich) | Одновременно сверху и снизу | Заглушки и драйверы | Сочетает преимущества нисходящего и восходящего методов |

### Интеграционное и системное тестирование

**Системное тестирование** проверяет программу целиком на соответствие требованиям в окружении, близком к рабочему. Интеграционное тестирование проверяет взаимодействие отдельных модулей и выполняется раньше системного.

### Пример 3. Модули проекта

#### А. Класс User

Файл `user.js`:

```js
class User {
  constructor(name, email, phone, id = null) {
    this.id = id;
    this.name = name;
    this.email = email;
    this.phone = phone;
  }
}

module.exports = User;
```

#### Б. Функция сравнения пользователей

Файл `user-comparer.js`. Пользователи сравниваются по данным без учёта `id`, так как `id` назначает база данных.

```js
// Сравнивает пользователей по данным, без учёта id
function areUsersEqual(a, b) {
  return a.name === b.name && a.email === b.email && a.phone === b.phone;
}

module.exports = { areUsersEqual };
```

#### В. Модуль доступа к данным

Файл `users-dal.js`. Значения передаются в запросы через знаки `?`, а не вставляются в текст запроса: так драйвер защищает запрос от SQL-инъекций (подробнее в практической работе №12).

```js
const mysql = require('mysql2/promise');
const User = require('./user');
const config = require('./db-config');

function toUser(row) {
  return new User(row.name, row.email, row.phone, row.id);
}

class UsersDAL {
  constructor() {
    this.pool = mysql.createPool(config);
  }

  async getAll() {
    const [rows] = await this.pool.query('SELECT id, name, email, phone FROM users ORDER BY id');
    return rows.map(toUser);
  }

  async add(user) {
    const [result] = await this.pool.query(
      'INSERT INTO users (name, email, phone) VALUES (?, ?, ?)',
      [user.name, user.email, user.phone],
    );
    user.id = result.insertId;
    return user;
  }

  async update(user) {
    const [result] = await this.pool.query(
      'UPDATE users SET name = ?, email = ?, phone = ? WHERE id = ?',
      [user.name, user.email, user.phone, user.id],
    );
    return result.affectedRows;
  }

  async deleteLast() {
    const [result] = await this.pool.query('DELETE FROM users ORDER BY id DESC LIMIT 1');
    return result.affectedRows;
  }

  async getByEmailDomain(domain) {
    const [rows] = await this.pool.query(
      'SELECT id, name, email, phone FROM users WHERE email LIKE ? ORDER BY id',
      ['%@' + domain],
    );
    return rows.map(toUser);
  }

  async getByPhonePrefix(prefix) {
    const [rows] = await this.pool.query(
      'SELECT id, name, email, phone FROM users WHERE phone LIKE ? ORDER BY id',
      [prefix + '%'],
    );
    return rows.map(toUser);
  }

  async close() {
    await this.pool.end();
  }
}

module.exports = UsersDAL;
```

### Пример 4. Интеграционные тесты

Файл `tests/users-dal.test.js`. Тесты обращаются к настоящей базе данных, поэтому перед каждым тестом таблица возвращается в исходное состояние: результат теста не зависит от предыдущих. После всех тестов пул соединений закрывается, иначе Jest не завершит работу.

Внимание: тесты очищают таблицу `users`. Не запускайте их на базе с нужными данными.

В примере приведены тесты на добавление и удаление. Тесты на обновление и выборку (пункты 5–7 задания 1) напишите самостоятельно, используя функции `update`, `getByEmailDomain` и `getByPhonePrefix`.

```js
const UsersDAL = require('../users-dal');
const User = require('../user');
const { areUsersEqual } = require('../user-comparer');

const dal = new UsersDAL();

// Перед каждым тестом таблица возвращается в исходное состояние
beforeEach(async () => {
  await dal.pool.query('TRUNCATE TABLE users');
  await dal.pool.query(
    `INSERT INTO users (name, email, phone) VALUES
      ('Иван Петров', 'ivan@ya.ru', '83012345678'),
      ('Анна Смирнова', 'anna@mail.ru', '88001234567'),
      ('Олег Сидоров', 'oleg@ya.ru', '89161234567'),
      ('Мария Козлова', 'maria@gmail.com', '83432223344')`,
  );
});

afterAll(async () => {
  await dal.close();
});

describe('UsersDAL и база данных usersmanaging', () => {
  test('добавляет нового пользователя с корректными данными', async () => {
    const newUser = new User('Пётр Иванов', 'petr@ya.ru', '88005553535');

    await dal.add(newUser);
    const users = await dal.getAll();

    expect(users).toHaveLength(5);
    expect(areUsersEqual(users[4], newUser)).toBe(true);
  });

  test('удаляет последнего пользователя', async () => {
    const before = await dal.getAll();

    const deleted = await dal.deleteLast();
    const after = await dal.getAll();

    expect(deleted).toBe(1);
    expect(after).toHaveLength(before.length - 1);
    expect(after.map((u) => u.id)).not.toContain(before[before.length - 1].id);
  });
});
```
