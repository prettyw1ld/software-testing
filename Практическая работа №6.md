# Практическая работа №6. Разработка через тестирование

## Цель работы

Практическое освоение принципов разработки программного обеспечения через тестирование (TDD) с использованием позитивного и негативного тестирования.

## Теоретические сведения

### Основные понятия

- **Тестирование** — проверка соответствия между реальным и ожидаемым поведением программы на определённом наборе тестов. Это одна из техник контроля качества ПО.
- **Верификация** — проверка соответствия целям, сформулированным в задании.
- **Валидация** — проверка соответствия ожиданиям пользователя.
- **Тест-кейс** — структура вида: действие — ожидаемый результат — тестовый результат.

Тест подтверждает или опровергает работоспособность кода. Проверка кода программистом вручную также является тестированием.

### Разработка через тестирование

**Разработка через тестирование** (Test Driven Development, **TDD**) — техника разработки ПО, основанная на повторении коротких циклов:

1. Пишется **тест**, покрывающий часть программы.
2. Пишется **код**, который позволяет пройти тест.
3. Выполняется **рефакторинг** нового кода в соответствии со стандартами.

**Рефакторинг** — контролируемый процесс улучшения кода без добавления новой функциональности. Он затрагивает только структуру и читаемость кода. Результат рефакторинга — чистый код и простой дизайн.

TDD делает программу проще и убирает лишние элементы. Он даёт уверенность в работоспособности программы в любой момент, а также помогает проектировать части программы так, чтобы их можно было использовать повторно и слабо связывать.

Цель TDD — соответствие спецификации, а не просто проверка кода. TDD помогает продумать требования и дизайн до написания функционального кода и относится к методам гибкого проектирования.

### Преимущества TDD

- **Рабочий код.** Правильно работающий код есть всегда, можно быть уверенным, что он работает как задумано.
- **Изменения без страха.** Тесты позволяют не бояться вносить изменения.
- **Живая документация.** В отличие от комментариев и длинной документации, тесты исполнимы. Поэтому при написании и рефакторинге тестов сохраняйте их читаемость и простоту алгоритма.
- **Архитектура через код.** Тесты заставляют думать о том, как будет использоваться объект или функция, и архитектура проявляется из кода сама.

### Модульное тестирование в TDD

**Модульный тест** (unit-тест) проверяет небольшие части кода: функции, методы классов и т. п. Порядок в TDD:

1. Пишется тест, который заведомо не проходит, до написания кода.
2. Пишется код, который проходит этот тест.

### Цикл красный — зелёный — синий

Базовый процесс TDD состоит из трёх этапов (зон). Основной принцип — разбиение больших задач на маленькие.

| Зона | Что делаем | Условие перехода к следующей зоне |
|---|---|---|
| **Красная** | Пишем тест, который упадёт с ожидаемой причиной | Тест падает по причине несоответствия результата ожиданию |
| **Зелёная** | Пишем простейший код, который проходит тест | Все тесты проходят |
| **Синяя** | Рефакторим код реализации и код тестов | Все тесты по-прежнему проходят |

#### Красная зона

Красная зона — состояние, в котором функция не проходит тест. В консоли упавшие тесты обычно отмечены красным.

Зона нужна, чтобы убедиться, что тест действительно проверяет то, что нужно. Например, из-за ошибки в самом тесте (перепутанные параметры) он может проходить всегда. Тест, который никогда не падает, ничего не проверяет, и такой тест не нужен.

Когда тест падает, внимательно изучите ошибку. Поломка должна происходить потому, что результат выполнения не совпадает с ожидаемым. Если тест падает по другой причине, он не проверяет предположение и ему нельзя доверять. Переходить к реализации в этом случае рано.

Первый тест для нового объекта должен быть простым. Все тесты красной зоны должны быть сфокусированы на разрабатываемой функциональности.

#### Зелёная зона

Цель зелёной зоны — пройти падающие тесты и убедиться, что ещё одна часть функциональности покрыта тестами. Цикл короткий, поэтому реализация должна быть максимально простой.

Зелёная зона означает, что заявленная функциональность работает как ожидается. Результатами можно поделиться с командой: другие разработчики смогут использовать проверенную функциональность при проектировании своих модулей, что сокращает время разработки проекта.

#### Синяя зона

Рефакторинг можно выполнять в любой момент: после одного или нескольких циклов красный — зелёный. Он безопасен, потому что затронутая функциональность уже покрыта тестами, и любая поломка будет сразу замечена. Так исключаются **регрессии**.

Рефакторить можно как код функции, так и код тестов. Тесты должны оставаться читаемыми и не содержать сложной логики, иначе придётся писать тесты для тестов.

## Задания

### Задание 1. Функция деления по TDD

Реализуйте по методу TDD функцию деления одного числа на другое с учётом обработки ошибок (неполный калькулятор). Все тесты — модульные. Выполняйте работу по образцу из раздела «Примеры».

1. Подготовьте проект и настройте Jest.
2. Реализуйте деление целых чисел без остатка (позитивный тест).
3. Выполните рефакторинг тестов: вынесите тестовые данные в массив тест-кейсов.
4. Расширьте функцию: результат с одним знаком после запятой для нецелых значений.
5. Реализуйте обработку ошибки деления на ноль (негативный тест).

Каждый шаг выполняйте по циклу: красная зона, зелёная зона, при необходимости синяя.

## Примеры

В примерах используются JavaScript, среда Node.js и фреймворк для модульного тестирования **Jest**. Назначение команд терминала описано в практической работе №5.

### Пример 1. Функция деления

#### А. Подготовка проекта

Если Jest не установлен, создайте проект и установите его:

```bash
mkdir tdd-divide
cd tdd-divide
npm init -y
npm install --save-dev jest
npm pkg set scripts.test="jest"
```

#### Б. Деление целых чисел

Первый тест — базовый случай: числа делятся без остатка, делитель не равен 0. Ожидается результат деления.

Красная зона. Создайте заглушку функции, чтобы тест падал из-за неверного результата, а не из-за отсутствия функции.

Файл `divide.js`:

```js
function divide(a, b) {
  return 0;
}

module.exports = { divide };
```

Файл `divide.test.js`:

```js
const { divide } = require('./divide');

test('делит целые числа без остатка', () => {
  expect(divide(10, 2)).toBe(5);
});
```

Запустите тесты командой `npm test`. Тест должен упасть с сообщением, что ожидалось `5`, а получено `0`:

```text
Expected: 5
Received: 0
```

Это нужная причина падения. Ошибка вида `divide is not a function` означает, что вы ещё не в красной зоне.

Зелёная зона. Реализуйте деление максимально просто:

```js
function divide(a, b) {
  return a / b;
}

module.exports = { divide };
```

Повторно запустите `npm test`: тест должен пройти.

#### В. Рефакторинг тестов

Один случай проверять недостаточно. Замените тест массивом тест-кейсов: каждый объект содержит аргументы функции и ожидаемый результат.

```js
const { divide } = require('./divide');

test.each([
  { a: 10, b: 2, expected: 5 },
  { a: 9, b: 3, expected: 3 },
  { a: 0, b: 5, expected: 0 },
])('divide($a, $b) возвращает $expected', ({ a, b, expected }) => {
  expect(divide(a, b)).toBe(expected);
});
```

Запустите тесты: все должны пройти. Тест остаётся простым и не содержит логики.

#### Г. Расширение функции: дробный результат

Нецелочисленный результат должен содержать один знак после запятой.

Красная зона. Добавьте в файл тестов ещё один блок `test.each`:

```js
test.each([
  { a: 7, b: 2, expected: 3.5 },
  { a: 10, b: 3, expected: 3.3 },
])('divide($a, $b) возвращает $expected', ({ a, b, expected }) => {
  expect(divide(a, b)).toBe(expected);
});
```

Тест для `10 / 3` должен упасть: функция возвращает `3.3333333333333335`, а ожидается `3.3`.

Зелёная зона. Округлите результат до одного знака:

```js
function divide(a, b) {
  return Math.round((a / b) * 10) / 10;
}

module.exports = { divide };
```

Запустите все тесты. Новый тест может не пройти, и старые тоже могут упасть. Тесты сразу показывают, что изменение нарушило обратную совместимость и портит уже проверенную функциональность. В этом случае исправьте реализацию, пока не пройдут все тесты.

#### Д. Обработка ошибки: деление на ноль

Красная зона. Добавьте негативный тест:

```js
test('выбрасывает ошибку при делении на ноль', () => {
  expect(() => divide(5, 0)).toThrow('Деление на ноль');
});
```

Тест должен упасть, потому что функция не выбрасывает ошибку (для `5 / 0` она возвращает `Infinity`):

```text
Expected substring: "Деление на ноль"
Received function did not throw
```

Зелёная зона. Добавьте проверку делителя:

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error('Деление на ноль');
  }
  return Math.round((a / b) * 10) / 10;
}

module.exports = { divide };
```

Запустите все тесты: все должны пройти.
